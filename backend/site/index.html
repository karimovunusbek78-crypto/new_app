Handbook for the backend team

Building the backend for the Gravitas Auto car marketplace

The Flutter app talks straight to Firebase; there is no server of our own yet. This page explains every collection and file the app uses, what is unsafe today, and what to build, in order.

App
Flutter · repo new_app, branch dev
Backend
Firebase Auth · Firestore · Storage
Users
Uzbekistan, UI in Russian

01Overview

People browse used cars in a list and in a vertical video feed. They like, save and favourite cars, comment and reply, follow sellers, and get in-app notifications. Two kinds of sellers publish:

  • Private seller: one car at a time ("Продажа авто").
  • Autosalon: a dealer page with logo, gallery, several locations on a map, and many cars.

Both need an admin's approval for each publication (chapter 05).

05Publish approval

Every publication (one car, or one autosalon publish) needs an admin's approval. The state lives in one document per user (pages/autoslon/permission/publish_permission.dart):

firestore
publish_permissions/{uid} {
  autoslonRequested : bool       // user asked to open an autosalon
  autoslonGranted   : bool       // ADMIN sets true to approve one publish
  carsellRequested  : bool       // user asked to sell one car
  carsellGranted    : bool       // ADMIN sets true to approve one listing
  updatedAt         : timestamp
}
sequenceDiagram
  actor U as User
  participant A as App
  participant DB as publish_permissions/{uid}
  actor S as Admin / support
  U->>A: Opens "Sell a car"
  A->>U: Shows WhatsApp, Telegram, phone buttons
  U->>A: Taps a contact button
  A->>DB: carsellRequested = true
  U->>S: Talks to support
  S->>DB: carsellGranted = true (console today)
  DB-->>A: Live update, form opens
  U->>A: Fills the form, publishes
  A->>DB: carsellGranted = false, carsellRequested = false

How an admin approves today

  1. Get the user's ID. The Telegram button sends «Мой ID: …» with it.
  2. Firebase console → Firestore → publish_permissions → open the document with that ID.
  3. Set carsellGranted (car) or autoslonGranted (autosalon) to true. The user's screen updates by itself.

Today a user can approve themselves. The app writes this document, so a modified app can set carsellGranted: true. The rules in chapter 07 allow only admins to set a …Granted flag to true. Give admins the custom claim below, then build a small admin page that calls a grantPublish function (chapter 08) instead of editing the console.

node · run once, locally
// npm i firebase-admin; use a service-account key, never commit it
const admin = require('firebase-admin');
admin.initializeApp({ credential: admin.credential.cert(require('./service-account.json')) });
admin.auth().setCustomUserClaims('ADMIN_UID_HERE', { admin: true })
  .then(() => console.log('admin claim set; the admin must sign out and back in'));

06Problems to fix

Found by reading the app's code. Work top to bottom.

P0

No security rules in the repo

Nobody can see what protects the live database. In "test mode" it is either open to anyone or starts rejecting everything when the test period ends. Check Firestore → Rules and Storage → Rules in the console today, then deploy the rules from chapter 07.

P0

Users can approve their own publications

The …Granted flags are written by the app. Fixed by the new rules; long term by the grantPublish function.

P0

Clients write other people's data

Any user can change any car's likesCount / viewsCount / savesCount, any user's subscribersCount, and create notifications for anyone. Phase 1 rules limit this to steps of ±1; phase 2 moves it to Cloud Functions.

P0

No admin role

Mark admins with the custom claim admin: true (chapter 05). The rules give admins full access.

P1

The permission is used up by the app

If the app crashes right after publishing, the permission stays and can be used again. Consume it in a function when cars/{id} or autosalons/{uid} is created.

P1

Deleting a car leaves junk behind

Its Storage files, its likedBy, savedBy, comments + replies and viewLog, and entries in other users' favorites and savedCars all stay. Add a cleanup function on car delete. Move deleteLog to a top-level deleted_cars collection so it stays findable.

P1

No push notifications

Notifications only appear while the app is open. Chapter 09 explains how to add them.

P1

Autosalon createdAt is overwritten

Every publish writes createdAt: serverTimestamp() with merge, so the dealer's start date keeps moving. Set it only when the document is created.

P1

Autosalon publish recreates all locations

All location documents are deleted and added again on every publish, so their ids change. Update them in place.

P2

The app loads every car at once

CarsProvider streams the whole cars collection, and search and filters run on the phone. Fine for hundreds of cars, not thousands. See chapter 10.

P2

Price, year and mileage are strings

They can't be sorted or filtered in Firestore. Add numeric copies priceNum, yearNum, kmNum filled by a function.

P2

viewLog grows forever

One document per view. Add a TTL policy on viewedAt (for example 90 days) or roll views up into daily counters.

P2

Car ids from a millisecond timestamp

Two people publishing in the same millisecond overwrite each other. Use collection('cars').doc().id.

P2

Geocoding calls Nominatim directly

Nominatim's usage policy requires a real User-Agent and at most one request per second for the whole app. Put a caching proxy function in front, or use a paid geocoder.

P2

Support contacts are hard-coded

The WhatsApp number, t.me/automarket_support and phone number are in the app code. Move them to Remote Config or a config/support document.

P2

Legacy users.canPublish

Still read by CarSellPermissionNotifier. Remove it once publish_permissions is the only source.

P2

No App Check

Turn on App Check (Play Integrity on Android, DeviceCheck / App Attest on iOS) so only the real app can call Firebase.

07Security rules

Phase 1 · now

Rules that fit the current app

  • Signed-in users read listings, profiles, comments, dealers
  • You write only your own profile, lists, likes, comments, cars, dealer page
  • Counters move only by ±1 (views by +1)
  • Only admins set …Granted = true
  • A car needs an active permission, or an existing autosalon
Phase 2 · after chapter 08

Lock counters and notifications

  • Functions own all counters and notifications
  • Remove the bumped(…) update branches
  • Remove the notifications create rule
  • The app stops writing those fields in the same release

Test before deploying. A wrong rule breaks the app for everyone at once. These rules have not run in the emulator yet.

  1. Start the emulators: firebase emulators:start --only auth,firestore,storage
  2. In a debug build, point the app at them in main.dart right after Firebase.initializeApp:
dart · debug only
if (kDebugMode) {
  await FirebaseAuth.instance.useAuthEmulator('localhost', 9099);
  FirebaseFirestore.instance.useFirestoreEmulator('localhost', 8080);
  await FirebaseStorage.instance.useStorageEmulator('localhost', 9199);
}
  1. Go through the whole checklist in chapter 11 with two test accounts.
  2. In the console's Rules Playground, confirm a normal user can't set carsellGranted: true, edit another user's car, or read another user's notifications.
  3. Deploy, and keep the previous version in the console's rules history so you can roll back in one click:

rules_version = '2';

// Firestore security rules for the new_app (Firebase project: gravitas-auto).
// Phase 1: they allow exactly what the current app version does, and block
// everything else. See backend/README.md, sections 5 and 6.
// Admins = accounts with the custom claim {admin: true}.

service cloud.firestore {
  match /databases/{database}/documents {

    function signedIn() { return request.auth != null; }
    function me() { return request.auth.uid; }
    function isAdmin() { return signedIn() && request.auth.token.admin == true; }
    function docPath(path) { return /databases/$(database)/documents/$(path); }

    // Only these keys differ between the stored and the written document.
    function onlyChanges(keys) {
      return request.resource.data.diff(resource.data).affectedKeys().hasOnly(keys);
    }
    function changesAny(keys) {
      return request.resource.data.diff(resource.data).affectedKeys().hasAny(keys);
    }
    // A counter moved by exactly +1 or -1 (FieldValue.increment from the app).
    function bumped(field) {
      return request.resource.data[field] is int
        && (request.resource.data[field] - resource.data.get(field, 0)) in [1, -1];
    }
    // Admin approved this user for one publication of the given type
    // ('carsell' or 'autoslon').
    function granted(type) {
      return exists(docPath('publish_permissions/' + me()))
        && get(docPath('publish_permissions/' + me())).data.get(type + 'Granted', false) == true;
    }
    function carOwner(carId) {
      return get(docPath('cars/' + carId)).data.ownerId == me();
    }
    function validText(t) { return t is string && t.size() > 0 && t.size() <= 2000; }

    // Admins can do anything (admin panel / support tools).
    match /{document=**} {
      allow read, write: if isAdmin();
    }

    // ------------------------------------------------------------ users
    match /users/{uid} {
      allow read: if signedIn();
      // Own profile. canPublish is a legacy admin flag: users may not set it.
      allow create: if signedIn() && me() == uid
        && !request.resource.data.keys().hasAny(['canPublish']);
      // Someone follows a user whose profile document does not exist yet.
      allow create: if signedIn() && me() != uid
        && request.resource.data.keys().hasOnly(['subscribersCount'])
        && request.resource.data.subscribersCount in [1, -1];
      allow update: if signedIn() && (
        (me() == uid && !changesAny(['canPublish', 'subscribersCount']))
        || (onlyChanges(['subscribersCount']) && bumped('subscribersCount'))
      );

      match /favorites/{carId} { allow read, write: if signedIn() && me() == uid; }
      match /savedCars/{carId} { allow read, write: if signedIn() && me() == uid; }

      // Profile change log: append-only.
      match /history/{id} {
        allow read: if signedIn() && me() == uid;
        allow create: if signedIn() && me() == uid && request.resource.data.changedBy == me();
      }

      match /notifications/{id} {
        allow read, delete: if signedIn() && me() == uid;
        allow update: if signedIn() && me() == uid && onlyChanges(['read']);
        // Phase 1: other users' apps write notifications. Phase 2 moves this
        // to Cloud Functions and this rule is removed.
        allow create: if signedIn() && me() != uid
          && request.resource.data.fromUid == me()
          && request.resource.data.type in ['like', 'comment', 'reply', 'subscribe']
          && request.resource.data.read == false;
      }
    }

    // ------------------------------------------------------------ cars
    match /cars/{carId} {
      allow read: if signedIn();
      allow create: if signedIn()
        && request.resource.data.ownerId == me()
        && request.resource.data.get('likesCount', 0) == 0
        && request.resource.data.get('viewsCount', 0) == 0
        && request.resource.data.get('savesCount', 0) == 0
        && (
          granted('carsell') || granted('autoslon')
          // an existing autosalon adds a car from its dashboard
          || (request.resource.data.get('isAutosalonCar', false) == true
              && request.resource.data.autosalonId == me()
              && exists(docPath('autosalons/' + me())))
        );
      allow update: if signedIn() && (
        (resource.data.ownerId == me()
          && !changesAny(['ownerId', 'likesCount', 'viewsCount', 'savesCount', 'createdAt']))
        || (onlyChanges(['likesCount']) && bumped('likesCount'))
        || (onlyChanges(['savesCount']) && bumped('savesCount'))
        || (onlyChanges(['viewsCount'])
            && request.resource.data.viewsCount == resource.data.get('viewsCount', 0) + 1)
      );
      allow delete: if signedIn() && resource.data.ownerId == me();

      match /likedBy/{uid} {
        allow read: if signedIn();
        allow create: if signedIn() && me() == uid && request.resource.data.uid == uid;
        allow delete: if signedIn() && me() == uid;
      }
      match /savedBy/{uid} {
        allow read: if signedIn();
        allow create, delete: if signedIn() && me() == uid;
      }
      match /viewLog/{id} {
        allow read: if signedIn() && carOwner(carId);
        allow create: if signedIn() && request.resource.data.viewerUid == me();
      }
      // Written by the owner right before deleting the car; kept for audit.
      match /deleteLog/{id} {
        allow create: if signedIn() && carOwner(carId) && request.resource.data.deletedBy == me();
      }

      match /comments/{commentId} {
        allow read: if signedIn();
        allow create: if signedIn() && request.resource.data.uid == me()
          && validText(request.resource.data.text)
          && request.resource.data.pinned == false;
        allow update: if signedIn() && (
          (resource.data.uid == me() && onlyChanges(['text', 'editedAt'])
            && validText(request.resource.data.text))
          || (carOwner(carId) && onlyChanges(['pinned']))
        );
        allow delete: if signedIn() && (resource.data.uid == me() || carOwner(carId));

        match /replies/{replyId} {
          allow read: if signedIn();
          allow create: if signedIn() && request.resource.data.uid == me()
            && validText(request.resource.data.text);
          allow update: if signedIn() && resource.data.uid == me()
            && onlyChanges(['text', 'editedAt']) && validText(request.resource.data.text);
          allow delete: if signedIn() && (resource.data.uid == me() || carOwner(carId));
        }
      }
    }

    // "Which cars did I like" — CarsProvider runs collectionGroup('likedBy').where('uid', ==, me).
    match /{path=**}/likedBy/{uid} {
      allow read: if signedIn();
    }

    // ------------------------------------------------------------ subscriptions
    // Document id = '{followerUid}_{targetUid}'.
    match /subscriptions/{id} {
      allow read: if signedIn();
      allow create: if signedIn()
        && request.resource.data.followerUid == me()
        && request.resource.data.targetUid != me()
        && id == me() + '_' + request.resource.data.targetUid;
      allow delete: if signedIn() && resource.data.followerUid == me();
    }

    // ------------------------------------------------------------ autosalons
    // Document id = owner uid.
    match /autosalons/{uid} {
      allow read: if signedIn();
      allow create: if signedIn() && me() == uid && granted('autoslon');
      allow update: if signedIn() && me() == uid && !changesAny(['ownerId']);

      match /locations/{id} {
        allow read: if signedIn();
        allow write: if signedIn() && me() == uid;
      }
    }

    // ------------------------------------------------------------ publish permissions
    // publish_permissions/{uid}: the user may ask (…Requested = true) and use up
    // a permission (…Granted = false). Only an admin may set …Granted = true.
    match /publish_permissions/{uid} {
      allow read: if signedIn() && me() == uid;
      allow create: if signedIn() && me() == uid
        && request.resource.data.get('autoslonGranted', false) == false
        && request.resource.data.get('carsellGranted', false) == false;
      allow update: if signedIn() && me() == uid
        && (!changesAny(['autoslonGranted']) || request.resource.data.autoslonGranted == false)
        && (!changesAny(['carsellGranted']) || request.resource.data.carsellGranted == false);
    }
  }
}
backend/storage.rules full file 
rules_version = '2';

// Firebase Storage rules for the new_app (project gravitas-auto).
// Everyone signed in can view media; only the owner can upload/delete
// inside their own folder. See backend/README.md, section 4.

service firebase.storage {
  match /b/{bucket}/o {

    function signedIn() { return request.auth != null; }
    function mb(n) { return n * 1024 * 1024; }
    // Deletes have no request.resource.
    function sizeOk(limitMb) {
      return request.resource == null || request.resource.size < mb(limitMb);
    }

    // avatars/{uid}.{ext}
    match /avatars/{file} {
      allow read: if signedIn();
      allow write: if signedIn()
        && file.matches(request.auth.uid + '[.][A-Za-z0-9]+')
        && sizeOk(10);
    }

    // cars/{ownerUid}/{carId}/photo_N.jpg and video.mp4
    match /cars/{uid}/{carId}/{file} {
      allow read: if signedIn();
      allow write: if signedIn() && request.auth.uid == uid
        && (file.matches('video.*') ? sizeOk(300) : sizeOk(15));
    }

    // autosalons/{uid}/logo_*, gallery/*, locations/*/*
    match /autosalons/{uid}/{allPaths=**} {
      allow read: if signedIn();
      allow write: if signedIn() && request.auth.uid == uid && sizeOk(300);
    }
  }
}

Example: likes

typescript · functions/src/index.ts
import { onDocumentCreated, onDocumentDeleted } from 'firebase-functions/v2/firestore';
import { onCall, HttpsError } from 'firebase-functions/v2/https';
import { setGlobalOptions } from 'firebase-functions/v2';
import { initializeApp } from 'firebase-admin/app';
import { getFirestore, FieldValue } from 'firebase-admin/firestore';

setGlobalOptions({ region: 'europe-west1' });
initializeApp();
const db = getFirestore();

export const onLike = onDocumentCreated('cars/{carId}/likedBy/{uid}', async (e) => {
  const { carId, uid } = e.params;
  const carRef = db.doc(`cars/${carId}`);
  const car = (await carRef.get()).data();
  if (!car) return;
  await carRef.update({ likesCount: FieldValue.increment(1) });
  if (car.ownerId && car.ownerId !== uid) {
    const from = (await db.doc(`users/${uid}`).get()).data() ?? {};
    await db.collection(`users/${car.ownerId}/notifications`).add({
      type: 'like', fromUid: uid, fromName: from.name ?? 'Пользователь',
      fromAvatarUrl: from.avatarUrl ?? null, carId, carName: car.name ?? null,
      commentId: null, text: null, read: false, createdAt: FieldValue.serverTimestamp(),
    });
  }
});

export const onUnlike = onDocumentDeleted('cars/{carId}/likedBy/{uid}', async (e) => {
  await db.doc(`cars/${e.params.carId}`)
    .update({ likesCount: FieldValue.increment(-1) })
    .catch(() => {});            // the car itself may already be deleted
});

Example: admin approval

typescript
export const grantPublish = onCall(async (req) => {
  if (req.auth?.token.admin !== true) throw new HttpsError('permission-denied', 'Admins only');
  const { uid, type } = req.data as { uid: string; type: 'carsell' | 'autoslon' };
  if (!uid || !['carsell', 'autoslon'].includes(type)) throw new HttpsError('invalid-argument', 'uid and type are required');
  await db.doc(`publish_permissions/${uid}`).set(
    { [`${type}Granted`]: true, updatedAt: FieldValue.serverTimestamp() },
    { merge: true },
  );
  return { ok: true };
});

export const consumeCarPermission = onDocumentCreated('cars/{carId}', async (e) => {
  const car = e.data?.data();
  if (!car || car.isAutosalonCar) return;
  await db.doc(`publish_permissions/${car.ownerId}`).set(

09Push notifications

  1. App (Flutter team): add firebase_messaging, ask for permission, and save the device token to users/{uid}/fcmTokens/{token} with platform and updatedAt. Refresh it on onTokenRefresh; delete it on sign-out.
  2. iOS: upload an APNs key in Firebase console → Project settings → Cloud Messaging.
  3. Backend: on users/{uid}/notifications/{id} create, send to every token and delete tokens FCM reports as invalid.

import { getMessaging } from 'firebase-admin/messaging';

const TITLES: Record<string, string> = {
  like: 'Новый лайк', comment: 'Новый комментарий', reply: 'Вам ответили', subscribe: 'Новый подписчик',
};

export const pushNotification = onDocumentCreated('users/{uid}/notifications/{id}', async (e) => {
  const n = e.data?.data();
  if (!n) return;
  const tokens = await db.collection(`users/${e.params.uid}/fcmTokens`).get();
  if (tokens.empty) return;
  const res = await getMessaging().sendEachForMulticast({
    tokens: tokens.docs.map((d) => d.id),
    notification: { title: TITLES[n.type] ?? 'Gravitas Auto', body: `${n.fromName}${n.carName ? ' · ' + n.carName : ''}` },
    data: { type: String(n.type), carId: String(n.carId ?? '') },
  });
  await Promise.all(res.responses.map((r, i) =>
    r.success ? null : tokens.docs[i].ref.delete()));
});

10Search & scale

Today the app downloads all cars and filters them on the phone (pages/search/search_page.dart). Plan this before the catalogue grows past a few thousand cars:

  1. Numbers as numbers. A function on car write parses price, year, km into priceNum, yearNum, kmNum (strip spaces and «км», «$»). Backfill existing cars once.
  2. Pagination. Home and feed load 20 cars at a time with orderBy('createdAt', 'desc').limit(20).startAfter(last).
  3. Filters on the server. Brand, body type, fuel and price range as Firestore queries with matching composite indexes, or
  4. A search service such as Typesense or Algolia, kept in sync by a function, for free-text search in Russian and Uzbek.
